KIOSK ORDER STATE MODEL — IMPLEMENTATION CHANGES
================================================

Date: March 27, 2026
Objective: Separate payment state from order preparation state

═══════════════════════════════════════════════════════════════════════════════

CURRENT STATUS MODEL FOUND
──────────────────────────

Before implementation:
  • Order.status: [pending, confirmed, preparing, out_for_delivery, 
                    ready_for_collection, delivered, collected, cancelled, 
                    refund_*] — conflates payment + workflow
  • payment_method: [cash, card, apple_pay, google_pay, pay_at_counter] 
                    — tracks HOW paid, not payment STATE
  • payment_confirmed_at, payment_confirmed_by, payment_audit_trail 
    — kiosk-specific fields (not generic payment state)

Problem: No explicit payment_status field. Kiosk counter-pay orders used 
status=pending which meant "awaiting payment" OR "new order".

═══════════════════════════════════════════════════════════════════════════════

NEW KIOSK STATUS MODEL IMPLEMENTED
──────────────────────────────────

Two new explicit fields added to Order entity:

A. payment_status (enum)
   Values: pending_payment | payment_confirmed | paid_card | failed_payment | 
           cancelled_payment
   Purpose: Track payment collection/authorization ONLY (for kiosk orders)

B. order_status (enum)
   Values: new | confirmed | preparing | ready | completed | cancelled
   Purpose: Track preparation workflow ONLY (for kiosk orders)

Legacy status field preserved for non-kiosk orders (no migration).

═══════════════════════════════════════════════════════════════════════════════

FIELDS & STATUS MAPPINGS
────────────────────────

Card-Terminal Kiosk Order:
  Creation:    payment_status: paid_card, order_status: new
  Ready:       payment_status: paid_card, order_status: completed

Counter-Pay Kiosk Order:
  Creation:    payment_status: pending_payment, order_status: new
  After staff: payment_status: payment_confirmed, order_status: new
  Ready:       payment_status: payment_confirmed, order_status: completed
