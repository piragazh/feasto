EXECUTIVE SUMMARY
════════════════════════════════════════════════════════════════════════════════

FINDING: Offline POS orders bypass all server validation during local creation 
and synced directly to the database without re-validation.

IMPACT: Staff could apply unlimited coupons, exceed discount thresholds, combine 
discounts, or inflate prices offline — all persisting to the database.

SEVERITY: HIGH — Financial and compliance risk

REMEDIATION: Implemented two-phase hardening:
  Phase 1: Block unsafe actions (coupons, discounts) offline
  Phase 2: Add sync re-validation + offline audit metadata

PHASE 2: SYNC RE-VALIDATION & AUDIT METADATA

  File: functions/syncOfflineOrder.js (NEW)
  ─────────────────────────────────────────
  Purpose: Replace direct Order.create() in sync path
  Flow:
    1. Authenticate and verify tenant access
    2. Re-fetch and recompute item prices from live menu
    3. Re-validate manual discount (manager cap 20%/£20, reason code required)
    4. Re-validate coupon (all checks: active, date range, min spend, limits)
    5. Enforce mutual exclusion (coupon XOR discount)
    6. If validation fails: mark needs_review=true with detailed notes
    7. If validation passes: create order with approved amounts
    8. Increment coupon usage_count server-side
  
  Result: Every offline order re-validated; invalid ones flagged ✓

  File: components/pos/POSOfflineSyncBanner.js
  ───────────────────────────────────────────
  Change: Line 48 — call syncOfflineOrder instead of Order.create()
  Was:    await base44.entities.Order.create(orderData)
  Now:    const syncResult = await base44.functions.invoke('syncOfflineOrder', orderData)
  Result: Sync path now re-validates ✓

  File: entities/Order.json
  ───────────────────────────
  Added Fields:
    offline_created: boolean          — identifies offline-sourced orders
    offline_created_at: date-time     — when created locally
    offline_synced_at: date-time      — when synced to server
    needs_review: boolean             — flagged if validation issues found
    sync_validation_notes: string     — audit details (why flagged)
    discount_reason_code: string      — was missing; now required for discounts
  
  Result: Full audit trail preserved ✓

POLICY IMPLEMENTED
════════════════════════════════════════════════════════════════════════════════

SAFE OFFLINE (ALWAYS ALLOWED):
  ✓ Full-price orders (no discount/coupon)
  ✓ Basic order capture (items, customer details)
  ✓ Status updates on existing orders
  ✓ Cash payment recording

BLOCKED OFFLINE:
  ✗ Coupons — entirely disabled; message shown
  ✗ Manual discounts — option A: disabled (safest) OR option B: capped + flagged
  ✗ Price edits — always from server
  ✗ Refund approvals — requires admin verification

FLAGGED FOR REVIEW ON SYNC:
  ⚠ All offline-created orders (offline_created=true)
  ⚠ Discount capping (if offline discount exceeded manager cap)
  ⚠ Coupon rejections (if offline coupon failed validation)
  ⚠ Price mismatches (if items re-priced on sync)

REMAINING ACCEPTABLE LIMITATIONS
════════════════════════════════════════════════════════════════════════════════

These limitations are unavoidable in an offline-first system. Mitigations exist.

1. COUPON REAL-TIME LIMIT ENFORCEMENT IMPOSSIBLE OFFLINE
   Why: No server round-trip available in offline mode
   Mitigation: Block coupons entirely offline ✓
   Impact: Safe; users forced to use online mode for discounts

2. MENU PRICE STALENESS OFFLINE
   Why: Cached menu from last online session
   Mitigation: Re-price items from live menu on sync ✓
   Impact: Acceptable; sync corrects prices

3. MANAGER DISCOUNT THRESHOLD NOT ENFORCED OFFLINE
   Why: No auth context in IndexedDB
   Mitigation: Re-validate on sync; flag if exceeded ✓
   Impact: Acceptable; sync catches violations

4. OFFLINE ORDER STALLS IF SYNC FAILS
   Why: Network unreliable
   Mitigation: Order remains pending; staff can retry manually ✓
   Impact: Acceptable; visible in offline banner

5. WALK-IN ORDERS (NO PHONE) CANNOT VERIFY COUPON LIMITS OFFLINE
   Why: No customer identity anchor
   Mitigation: Block coupons entirely offline ✓
   Impact: Acceptable; walk-in orders use cash/full-price

ATTACK PATHS CLOSED
════════════════════════════════════════════════════════════════════════════════

COUPON ABUSE (UNLIMITED REDEMPTION)
  Before: Coupon applied offline without validation; syncs unlimited times
  After:  Coupon dialog blocked offline entirely
  Status: ✓ CLOSED

DOUBLE DISCOUNT (COUPON + MANUAL)
  Before: Both discounts applied offline; mutual exclusion not enforced
  After:  Coupon blocked offline; if both present on sync, coupon removed
  Status: ✓ CLOSED

MANAGER DISCOUNT BYPASS
  Before: Manager applies 50% discount offline (above 20% cap); syncs as-is
  After:  Discount capped to £20/20% on sync; order flagged for review
  Status: ✓ CLOSED

MENU PRICE MANIPULATION
  Before: Item prices hardcoded in offline order; never re-checked
  After:  Items re-priced from live menu on sync; total recalculated
  Status: ✓ CLOSED

COUPON USAGE RACE CONDITION
  Before: usage_count incremented offline (or not at all); race condition possible
  After:  usage_count incremented server-side only, after order persists
  Status: ✓ CLOSED

NO AUDIT TRAIL FOR OFFLINE ORDERS
  Before: No way to identify offline-created orders
  After:  offline_created=true, offline_created_at, offline_synced_at, needs_review
  Status: ✓ CLOSED
